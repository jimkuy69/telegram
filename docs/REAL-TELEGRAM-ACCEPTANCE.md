# Real Telegram Acceptance Runbook

เอกสารนี้ใช้ทดสอบ Telegram Control Studio บน Windows ด้วยบัญชีทดสอบและผู้รับที่ยินยอมเท่านั้น ไม่ใช้บัญชีหลัก ไม่ส่งแบบจำนวนมาก และไม่ใช้เพื่อหลบข้อจำกัดของ Telegram

## 0. ขอบเขตที่ต้องยืนยันก่อนเริ่ม

- ใช้ Telegram User Account สำหรับทดสอบโดยเฉพาะ
- ใช้ผู้รับ 1 คนที่ยืนยันความยินยอมแล้ว
- เตรียมข้อความทดสอบที่ไม่เป็นสแปม
- ห้ามใส่ OTP, 2FA Password, API Hash หรือ Session ลงใน Issue, Log, Screenshot หรือแชต
- ตรวจสอบว่า Windows Installer เป็นรุ่นล่าสุดจาก GitHub Actions และติดตั้งในโฟลเดอร์ข้อมูลผู้ใช้ตามที่โปรแกรมกำหนด

## 1. ตรวจการติดตั้งและการตั้งค่า

1. เปิด Telegram Control Studio
2. เปิดเมนู **ตั้งค่า**
3. ตรวจว่า Telegram API ID แสดงอยู่ โดยไม่เปิดเผย API Hash บนภาพหน้าจอ
4. ตรวจว่า Native TDLib แสดงสถานะเชื่อมต่อแล้ว และ Hash Gate ผ่าน
5. ปิด Settings แล้วเปิดใหม่ ตรวจว่าค่าการตั้งค่ายังอยู่
6. เปิดเมนู **เพิ่มบัญชี**
7. กรอกชื่อแสดงผลและเบอร์โทรศัพท์ในรูปแบบสากล เช่น `+66...`
8. รับ OTP จาก Telegram ในแอปหรือช่องทางที่ Telegram แสดงให้เห็น แล้วกรอกเฉพาะในช่องของโปรแกรม
9. ถ้ามี 2FA ให้กรอกในช่อง 2FA เท่านั้น
10. รอจนสถานะบัญชีเป็น **Ready** แล้วจึงปิดหน้าต่าง

ผลที่คาดหวัง: ไม่มี Credential ปรากฏใน Log และบัญชีที่เลือกด้านบนแสดงสถานะ Ready

## 2. ทดสอบข้อมูลแบบอ่านอย่างเดียว

1. เลือกบัญชีที่สถานะ Ready จากตัวเลือกด้านบน
2. กด **Sync TDLib** ในหน้า Contacts
3. ตรวจจำนวน Contacts และเวลา Sync
4. เปิด **กลุ่มและแชนแนล** แล้วกด Sync จาก TDLib
5. เลือกกลุ่ม/แชนแนลหนึ่งรายการ
6. กด **ดูสมาชิก/รายละเอียด** ถ้ารายการนั้นและสิทธิ์รองรับ
7. ตรวจว่าโปรแกรมแสดงข้อจำกัดเมื่อ Telegram ไม่เปิดเผยข้อมูลครบ

ผลที่คาดหวัง: ข้อมูลในหน้าจอเป็นข้อมูลที่ Telegram ส่งกลับมาเท่านั้น และไม่มีการสรุปเกินจริงว่าเป็นสมาชิกทั้งหมด

## 3. ทดสอบ Consent และ Opt-out

1. กลับหน้า **ส่งข้อความ**
2. เลือกผู้รับที่ยินยอม 1 คน
3. ตรวจสถานะผู้รับเป็น **ได้รับความยินยอม**
4. อย่าเลือกผู้รับที่เป็น Opt-out หรือยังไม่อนุญาต
5. หากต้องการทดสอบ Opt-out ให้เปลี่ยนสถานะผู้รับทดสอบ แล้วตรวจว่าระบบไม่นำผู้รับนั้นเข้า Job

หมายเหตุ: ช่องสี่เหลี่ยมด้านซ้ายของแต่ละแถวคือ checkbox เลือกผู้รับ และช่องบนหัวตารางคือเลือกผู้รับที่แสดงอยู่ทั้งหมด หาก checkbox กดไม่ได้ ให้ตรวจว่าตารางโหลดเสร็จแล้วและบัญชีเป็น Ready ก่อนสร้าง Job

## 4. ทดสอบ Preview โดยยังไม่ส่งจริง

1. กรอกข้อความทดสอบสั้น ๆ
2. เพิ่มลิงก์เฉพาะเมื่อจำเป็น
3. ตรวจ Preview
4. กด **ถัดไป: ตรวจสอบ**
5. ตรวจจำนวนผู้รับและข้อความเตือน Consent/Opt-out
6. กดสร้าง Preview/Job ตามที่หน้าจอระบุ
7. ตรวจ Activity Log ว่าเป็น `JobCreatedWaitingForConfirmation`

ผลที่คาดหวัง: Preview ไม่ส่งข้อความจริง และ Job อยู่สถานะรอการยืนยัน

## 5. ทดสอบส่งจริงแบบ 1 ผู้รับ

1. สำรองข้อมูลก่อนเริ่ม
2. เลือกผู้รับที่ยินยอมเพียง 1 คน
3. ตรวจ Preview อีกครั้ง
4. กดปุ่ม **ยืนยันและส่งจริง**
5. ยืนยันในกล่องยืนยัน
6. รอผลใน Queue และ Activity Log
7. ตรวจข้อความที่ปลายทางด้วย Telegram จริง
8. ตรวจผลรายรายการว่า Completed หรือ Failed พร้อมเหตุผล

ห้ามกดซ้ำระหว่างงานกำลังทำงาน หากเกิด FloodWait ให้รอตามเวลาที่ Telegram ระบุ ห้ามหมุนบัญชีหรือพยายามหลบ Limit

## 6. ทดสอบ Queue และการกู้คืน

1. สร้าง Preview Job แต่ยังไม่ส่ง หรือส่ง Job ทดสอบ 1 รายการ
2. เปิดเมนู **คิวงาน/ประวัติ** ตรวจสถานะ Draft, WaitingForConfirmation, Queued, Running และ Completed
3. ปิดโปรแกรมระหว่าง Preview หรือหลังสร้าง Job
4. เปิดโปรแกรมใหม่
5. ตรวจว่าบัญชี สถานะ Job และรายการ Audit ยังอยู่
6. ห้าม Resume งานส่งจริงจนกว่าจะตรวจผู้รับและ Preview ใหม่

## 7. ทดสอบ Invite Link แบบปลอดภัย

1. เปิด **Invite Links**
2. เลือกกลุ่ม/แชนแนลที่ตนเองดูแล
3. สร้างลิงก์โดยกำหนด Expiration และ Usage Limit ต่ำ
4. เปิด Join Request หากต้องการทดสอบ
5. ใช้บัญชีทดสอบที่ได้รับอนุญาตส่ง Join Request
6. เปิด **Pending Requests** แล้ว Approve/Reject
7. ตรวจ Audit Log

ไม่ทดสอบ Direct Invite กับผู้ที่ไม่ได้ยินยอม

## 8. Backup และ Restore

1. ปิด TDLib session/ออกจากบัญชีตามขั้นตอนของโปรแกรม
2. เปิด Settings และสร้าง Encrypted Backup
3. ตรวจว่าไฟล์ Backup ไม่ใช่ Plaintext และเก็บไว้นอกโฟลเดอร์ติดตั้ง
4. ใช้สำเนาทดสอบเพื่อ Restore เท่านั้น
5. ตรวจว่าระบบเตือนเรื่องการเขียนทับ Database และให้ Restart
6. เปิดโปรแกรมใหม่ ตรวจบัญชี การตั้งค่า Job และ Audit

## 9. หลักฐานที่ต้องเก็บ

เก็บเฉพาะข้อมูลที่ไม่เป็นความลับ:

- รุ่น Installer และวันที่ทดสอบ
- Commit SHA หรือ Workflow Run
- ขั้นตอนที่ทดสอบ
- สถานะที่เห็นใน UI
- จำนวนรายการโดยรวม
- Job ID ที่ไม่เปิดเผยข้อมูลลับ
- ภาพหน้าจอที่ปิดบังชื่อ เบอร์ Username และ ID ของผู้ใช้
- Activity Log ที่ Redact แล้ว

ห้ามเก็บหรือส่ง:

- OTP
- 2FA Password
- API Hash
- Session
- Token
- Database หรือ Backup จริง

## Acceptance Gate

ผ่านเมื่อครบทุกข้อ:

- [ ] Native TDLib เชื่อมต่อได้
- [ ] บัญชีทดสอบเป็น Ready
- [ ] Sync Contacts ได้
- [ ] Sync Groups ได้ตามสิทธิ์
- [ ] Preview ไม่ส่งจริง
- [ ] ส่งจริงสำเร็จถึงผู้รับที่ยินยอม 1 คน
- [ ] Opt-out ถูกบล็อก
- [ ] Queue และ Activity Log แสดงผลถูกต้อง
- [ ] ปิด/เปิดโปรแกรมแล้วกู้สถานะได้
- [ ] Invite Link/Join Request ทำงานตามสิทธิ์
- [ ] Backup/Restore ผ่าน
- [ ] ไม่มี Secret ใน Log หรือหลักฐาน
